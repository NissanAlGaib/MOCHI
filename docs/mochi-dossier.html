01What a request actually passes through

MOCHI is a reverse proxy speaking the OpenAI chat-completions API, so adoption is a base-URL change rather than a code restructure. Everything below happens between the client's request and the upstream model, and again on the way back.

Phase 4SegmentSplit by source tag; assign trust level
Phase 3NormalizeNFKC, homoglyphs, invisible chars, decode chains
Phase 6Stage I47 regexes, severity-tiered, windowed
Phase 8Stage IIE5 encoder + attention pooling
Phase 7Session risk5-turn rolling window, upgrade-only
Phase 9Stage IIILLM arbiter — off by default
Phase 10EnforceALLOW / BLOCK / SANITIZE
—Upstream LLMForwarded, streaming preserved
Phase 11OutboundExfiltration URLs, verbatim disclosure
Phase 2TelemetryStructured JSONL record

The organising principle across enforcement and outbound handling is the same: the action targets the segment that is guilty. A user who types an override instruction is the attack, so the request is blocked. A poisoned web page inside an otherwise legitimate request is not the user's fault, so the payload is redacted and the real question is served. That asymmetry is what the six-tag source taxonomy exists to support.

02Algorithms, and how each one works

Nine mechanisms carry the system. For each: what it does, how it works, and the measurement that made it necessary — several were chosen against the library default because a number said the default was wrong.

Unicode NFKC normalization + homoglyph folding Built

mochi/preprocess/normalize.py:145 · fold_homoglyphs, dominant_script

Applies Unicode NFKC compatibility decomposition, then strips zero-width and bidirectional-control characters, then maps Cyrillic and Greek lookalikes onto Latin.

The third step exists because NFKC alone does not fold homoglyphs — Cyrillic "а" and Latin "a" are genuinely distinct characters, not compatibility variants, so homoglyph substitution survives standard normalization untouched. A separate confusables table is the only thing that catches it.

Iterative multi-layer decoding Built

mochi/preprocess/normalize.py:268 · unwrap_encodings

Attempts base64, hex, URL-encoding and ROT13 decodes in a loop up to MAX_DECODE_DEPTH = 3, gated by a readability heuristic so random API keys and hashes are not surfaced as "decoded text".

The guiding rule is reveal, never discard: decoded payloads are appended as extra scannable variants rather than replacing the original, because both forms carry signal — the original proves obfuscation was attempted, the decoded form shows what it hid. The depth cap is a resource-exhaustion guard, since nested decoding expands geometrically under attacker control.

Sliding-window chunking with boundary snapping Built

mochi/detect/chunking.py · shared by both detection stages

Splits text into overlapping character windows, nudging each cut to the nearest whitespace within 64 characters. Stage I uses 20,000-char windows with 512 overlap; Stage II uses a character budget derived from the 512-token encoder limit with 25% overlap.

Overlap must exceed the longest matchable span, or a payload straddling a boundary is invisible to both windows — zero-overlap chunking merely trades silent truncation for silent splitting. Justified by measurement: the malicious span occupies a median 3.4% of its document, and 14.8% of locatable attacks sit in the document tail, so truncation is the common case for indirect injection rather than an edge case.

Stage I — compiled regex set with severity tiers Built

mochi/detect/stage1_syntactic.py · patterns in mochi/patterns.json

47 regexes and 13 normalization-flag rules across 9 detectors, compiled once per process and cached. Each detector reports at most one detection per scan, keeping the most severe. Only high-severity matches block; medium and low become signals that feed session risk.

The tiering is a false-positive control. Several patterns from the original specification — bare \bOR\b, \bDAN\b, \bbash\b — match ordinary English and would have destroyed the FPR < 1% target outright. Context was tightened for the same reason: ignore previous became ignore … previous <instruction|rule|…>, because the attack always names what it is overriding while "ignore previous emails" does not.

Stage II — E5 encoder with attention pooling Not yet trained

training/model.py:39 · intfloat/multilingual-e5-small

A multilingual E5 encoder with a learned attention-pooling head over token representations, scored chunk-by-chunk with the maximum taken across windows. Thresholds: below 0.45 passes, at or above 0.55 blocks, the band between is resolved by source trust.

Mean pooling — the sentence-transformers default — computes 0.966 × benign + 0.034 × attack at the measured payload share, landing the document vector almost entirely in benign territory. This is the textbook multiple-instance-learning problem: the bag carries the label, a few instances carry the evidence. Attention pooling lets a 3% span dominate, and the learned weights double as the token attribution that makes SANITIZE implementable. (Ilse, Tomczak & Welling, ICML 2018.)

Session risk accumulation Built

mochi/session/risk_accumulator.py:41 · window 5, threshold 1.0

A per-session rolling deque of the last 5 turn risks. Non-blocking Stage I signals contribute by severity (low 0.15 / medium 0.35 / high 0.70); when the window sum crosses 1.0, escalation triggers. Sessions are LRU-capped at 10,000 with a 30-minute idle TTL.

Targets the multi-step priming chain, where three turns each score 0.38–0.43 — under the 0.45 benign threshold — and a stateless pipeline allows all three. Critically, session risk only upgrades an existing weak signal; it never invents one. A clean turn in a risky session is still allowed, because escalating on history alone would permanently degrade a session on one unlucky sequence with no evidence attached to the request being judged.

Guilt-targeted enforcement with verified redaction Built

mochi/mitigate/sanitizer.py:53 · ALLOW / BLOCK / SANITIZE

Maps detections to an action based on which segment is guilty and how much authority its source carries. Redaction replaces the span with a deliberately inert marker containing no imperative verb and no addressee.

Two details are load-bearing. A marker reading "IGNORE THE ABOVE" would itself be an injection, so the replacement text is chosen to be unreadable as an instruction. And a SANITIZE that cannot verify it removed the payload escalates to BLOCK — the alternative is the worst available outcome, where the log claims mitigation while the attack passes upstream intact.

Outbound URL risk — two independent axes Built

mochi/mitigate/url_scanner.py · mochi/mitigate/outbound.py:41

Scores each URL in the model's response on two axes: does it fetch without user action (markdown image, <img src>) and does it carry opaque data outward (long base64-ish query values). Disclosure is detected by 8-word n-gram overlap against protected text.

Both axes are required because either alone over-fires: blocking every auto-fetched image breaks legitimate image output, and blocking every URL with a query string breaks search links and pagination. Only the combination — fetched without consent, carrying opaque data — has no benign explanation. Disclosure detection is verbatim-only on purpose; detecting paraphrase would require a semantic model of what each deployment considers secret, which MOCHI does not have and will not pretend to.

Statistical apparatus Built

eval/token_association.py:60 · eval/stats.py · eval/baseline_models.py

Token–class association uses the chi-square test of independence on 2×2 contingency tables, with Fisher's exact test substituted whenever an expected cell count falls below 5, and Benjamini–Hochberg FDR control across the whole vocabulary. Effect size is reported as Cramér's V and log-odds with Haldane–Anscombe correction. Model comparison uses a paired t-test with Cohen's d, confidence intervals, and an explicit normality check.

Chi-square rather than correlation because both variables are binary categorical — Pearson's r assumes continuous variables and point-biserial still needs one continuous side; both would be the wrong instrument. Yates' correction is deliberately omitted as over-conservative at this sample size. The normality check exists because the thesis originally asserted normality rather than testing it.

Cramér's V is the wrong instrument for this question — it is symmetric and penalises rarity, and every bigram is rarer than its parts, so peak V cannot rise. What moves is contamination: the share of a term's occurrences sitting on benign text, which is the false-positive rate that term would produce as a Stage I rule.

Same phrase family, an 83× cleaner indicator, and a lower V (0.198 vs 0.211). Reporting V alone would have hidden the finding entirely. Recommendation: n = 1–2; trigrams add 11,568 terms and make contamination marginally worse.

Token–class association

Across 82,765 samples (35,838 malicious / 46,927 benign), 10,013 tokens at document frequency ≥ 30 were tested. 4,727 remained significant after Benjamini–Hochberg correction at FDR 0.05 — 47.2% of the vocabulary. The strongest single effect is instructions at Cramér's V = 0.291, and only 126 tokens (1.3%) reach V ≥ 0.10 at all. At this sample size significance is nearly free; effect size carries the finding.

Findings that changed the methodology

  • deepset is fully redundant. All 546 rows appear in jayavibhav already (550 exact-match pairs). Including it would have inflated the reported corpus size while adding zero new examples. Moved to data/excluded/, where the loader's non-recursive glob ignores it but the rejection stays re-verifiable.
  • Cross-dataset leakage exists. 17 exact and 97 near-duplicate pairs between jayavibhav and promptshield_test, plus 29 near-duplicates between PromptShield's own train and validation splits. Untreated, this is train/test contamination that inflates every downstream number.
  • 254 rows carry contradictory labels — byte-identical text labelled both benign and malicious across sources. An irreducible noise floor no classifier can cross.
  • Signal position is not uniform. Of 310 locatable attack spans, 169 sit in the document head, 95 in the middle, and 46 (14.8%) in the tail. Any head-truncating detector silently discards roughly one attack in seven — which is precisely why both stages window rather than truncate.
  • jayavibhav dominated at 86% of the raw corpus. Left uncapped, a Stage II classifier optimises for that one distribution and PromptShield — the application-representative source with a peer-reviewed paper behind it — becomes a rounding error. The 40,000-row cap is a representativeness measure, not a token-cost measure.

08Gaps, by how much they threaten the claims

Ordered by risk to the thesis rather than by effort. The first three are the ones that would be asked about at a defence.

Stage II has never been trained Critical

No models/ directory exists. Every Stage II code path is exercised through a stub scorer, which validates the plumbing but produces no accuracy number. The system's headline claim — that semantic detection closes the 5.2% recall gap — is currently unevidenced.

Everything needed is in place: training/finetune_e5.py, an RTX 4070 with 8 GB, and a cleaned corpus. At 8 GB the specified batch size of 32 at 512 tokens will need fp16 or gradient accumulation.

Stage I and the baselines measured on different corpora Resolved

Stage I re-run on data/clean/: precision 0.9728, recall 0.0590, F1 0.1112, FPR 0.00126. Every number in this dossier now comes from the same 82,765-row corpus. The raw-tree figures are retained in reports/stage1.json for provenance only.

The corpus teaches shortcuts, and the bias is broader than first measured Upgraded to critical

The word-cloud figure surfaced more than the token table did. Benchmark artifacts are as expected — pwned (2,789 malicious / 0 benign), kermode, kermodei, gribbell, ursus, americanus, few_shot_examples, sda, yool: 14 of the top 150.

The unexpected part is a large Spanish block sitting among them: gracias, esta, volvi, libro, biblioteca, hola, gusta, donde, clave, por, sido, negro, secreta. This is not three stray tokens — it is a systematic pattern.

The corpus does not merely contain benchmark markers; it teaches that non-English text is malicious. That makes the A14 Taglish evaluation a requirement rather than an enhancement, and it means benign-Taglish false-positive rate must be reported separately from the pooled FPR.

No Tagalog or code-switched evaluation data Significant

The encoder is already multilingual (intfloat/multilingual-e5-small), so the model layer is not the obstacle — but there is no code-switched test set, so multilingual robustness is currently an assumption. Note that dominant_script() detects mixed Unicode script, not mixed language; the two are unrelated for Taglish, which is Latin script throughout.

Token association is unigram-only Resolved

--ngram-max and --ablation added, unigram default preserved so previously cited figures stay reproducible. The finding: benign contamination among the top 50 associations falls from 22.1% to 13.5% at bigrams, while peak Cramér's V does not move at all — V penalises rarity and is the wrong instrument here.

Committed coverage report stale by 23 points Resolved

Regenerated: 30 modules, 92% over 2,064 statements, 454 tests passing.

Ten feature columns are constant on this corpus Significant

html_stripped, hidden_css_detected, html_comment_extracted, attribute_text_extracted, file_metadata_extracted, has_bidi and four resource guards never vary across all 82,765 rows.

Not a bug in the extractor — the corpus is almost entirely short plain-text prompts, so the HTML and file-extraction paths never fire. It is the same representativeness limit already recorded for Stage II dilution: this corpus cannot exercise the indirect-injection channels MOCHI is built to defend. Those columns will carry signal only against a document-bearing fixture set, which does not yet exist (register item D11).

Phases 12–14 not started Planned

Multi-provider adapters, full evaluation, and packaging remain. The gateway currently speaks only the OpenAI dialect, so the "provider-agnostic" framing is a design intention rather than a demonstrated property.

Session state is single-instance by design Accepted

An in-process dict means risk accumulation is incorrect across replicas. Deliberate and documented — the evaluated deployment is single-instance — but it bounds any deployment claim, and is worth stating before a panel does.

Weakest-covered modules are the extraction paths Minor

preprocessor.py at 63% and file_extract.py at 65%. PDF extraction in particular is an untrusted-input surface, which is where thin coverage matters most.
